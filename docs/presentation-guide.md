# 발표 준비 가이드

2026-11-01 기준 소스 코드와 `submission/deck/index.html`, `docs/CodySafe 발표자료 (유레카).pptx`를 비교한 결과입니다. 2차 대면 심사는 발표 7분(라이브 시연 3분 이상, 설명 4분 이내)과 Q&A 5분입니다.

## 1. 어떤 발표자료를 쓸 것인가

제출과 발표에는 `submission/유레카_발표자료.pdf`를 씁니다. PPTX는 URL 검사 중심의 초기 기획이라 현재 서비스와 맞지 않으며, 디자인을 참고할 때만 사용합니다.

| PPTX 슬라이드 | 현재 내용 | 소스 코드 기준 |
|---|---|---|
| 3~5 해결 방안, 기능, 기술 | 체험, URL 검사, 대응 안내 | URL 탐지는 폐기. 통화 녹음 → STT → 판정 → 근거 대조 → 가족 알림·금융 앱 잠금 |
| 3~4 시뮬레이션 | 6가지 수법 | 13개 시나리오 |
| 4, 10~11 가족 공유 | 계획 | 가족 알림, 암구호, 잠금 해제 모두 구현 |
| 5, 7 LLM과 백엔드 | 모델 선정 전, 계획 | Claude, 자체 Whisper, RAG, FastAPI 구현 |
| 6 개인정보 | 기기 안에서 검사 | 음성은 서버와 S3로, 글자 기록은 Anthropic으로 전송 |
| 8 역할 | 확인 필요 | 구체적인 기여 내용을 기입 |
| 9 외부 자원 | 확인 필요 | 실제 사용 내역을 전부 기입 |

## 2. 고칠 내용

### 발표 전 필수

| 항목 | 현재 | 조치 |
|---|---|---|
| OpenAI 전환 조건 | 발표자료에는 "부하·장애 때만"으로 적혀 있으나, 300초 또는 50 MiB를 넘는 음성도 전환됨 (`stt_client.py`, `providers.py`) | 문구에 "5분 초과"를 추가. 긴 통화를 자체 처리하려면 구간 분할을 구현 |
| 음성 보관 | 시연 서버가 `keep_audio: true`. 사용자가 기록을 지우기 전까지 음성이 남음 | 시연 서버에서 끄거나 "시연 환경은 보관, 운영은 분석 후 삭제"로 설명. 보관 설정은 기간 제한도 함께 검토 |
| 평문 구간 | 앱·브라우저와 서버 사이가 HTTP이고 앱이 평문 통신을 허용함 | HTTPS로 전환하거나 1단계 과제로 먼저 밝힘 |
| 임시 업로드 링크 | 유효 시간 1시간 (`providers.py`) | 5분 정도로 줄이거나, "짧은 시간"이라고 표현하지 않음 |
| 외부 자원 | 저장소의 공용 화면이 Pretendard를 쓰지만 발표자료 목록에 없음 | 발표자료 ⓕ에 Pretendard 1.3.9(OFL) 추가 |
| 제출 체크리스트 | ElevenLabs 사용처, 팀원의 AI 코딩 도구, 검색 데이터 이용 조건이 미확인으로 남음 | 팀원에게 확인 후 반영 |
| 소스 코드 해시 | 커밋할 때마다 달라짐 | 마지막 커밋 뒤 `유레카_소스코드.txt`에 기입 |

### 표현 정리

- **RAG 비교:** 탐지와 오탐은 같지만 잠금은 18건에서 19건으로, 판단 어려움은 0건에서 1건으로 달라졌습니다. README의 "판정 차이 없음"은 "탐지·오탐 차이 없음"으로 고칩니다.
- **탐지 30건:** 가족 알림은 22건, 잠금은 18건입니다. 나머지 8건은 기타 사기로 판정되어 설계상 조치하지 않습니다. "30건 모두 탐지"만 말하지 말고 함께 설명합니다.
- **확신도:** 사기 확률이라고 부르지 않습니다. LLM이 매긴 보정 전 값입니다.

## 3. 어필할 내용

심사 기준의 "단순 호출이 아닌 직접 개발"에 맞춰, API를 호출한 뒤 직접 만든 안전장치를 중심으로 말합니다.

1. **탐지 다음 단계를 맡는 포지션:** 일반 앱은 통화 음성을 받을 수 없어 실시간 탐지는 제조사와 통신사 영역입니다. 그래서 탐지 뒤의 행동을 맡습니다. 금융 앱 잠금과 가족 암구호까지 잇는 서비스는 공개 자료에서 찾지 못했습니다.
2. **LLM을 그대로 믿지 않는 구조:** 인용 문장이 녹취에 순서대로 있는지 코드로 검사하고, 근거가 없으면 판단 어려움으로 낮춰 알림과 잠금을 막습니다 (`llm.py`의 `_keep_grounded`).
3. **오탐 피해를 고려한 단계적 조치:** 알림은 0.7, 잠금은 0.9로 기준을 나눴습니다. 잠금은 가족 해제, 본인 10분 대기, 시간 만료로 되돌릴 수 있습니다.
4. **사생활을 지키는 가족 보호:** 가족에게는 의심 여부와 잠금 상태만 전달합니다. 요약, 유형, 녹취, 확신도는 보내지 않습니다.
5. **근거를 갖춘 STT 선택:** 5개 설정을 직접 비교해 CER 3.33%, RTF 1.17인 turbo INT8을 골랐습니다. CER이 가장 낮은 large-v3(3.02%)는 RTF가 2.08이었습니다. 합성 음성 20개 기준이라는 점을 함께 말합니다.
6. **실제 폰에서 이어지는 동작:** 녹음 폴더 감지부터 판정, 경고, 금융 앱 차단까지 실제 폰에서 확인했고, 자동 테스트 71개가 통과합니다.
7. **AI 음성 시대의 확인 수단:** 목소리 대신 매일 바뀌는 가족 암구호로 본인을 확인합니다.
8. **측정한 것과 아닌 것을 구분하는 태도:** 합성 평가의 신뢰구간과 실제 통화 미측정을 먼저 밝히고, 실제 통화 500건 평가 계획으로 연결합니다.

## 4. 7분 구성

| 시간 | 내용 |
|---|---|
| 0:00~0:50 | 문제: 끊은 뒤에도 이어지는 피해, 혼자 판단하기 어려운 상황 |
| 0:50~1:30 | 포지션: 왜 통화 후인가, 왜 가족인가 |
| 1:30~4:40 | 라이브 시연: 새 녹음 감지 → 판정과 근거 → 금융 앱 차단 → 가족 알림 → 암구호 확인과 해제 |
| 4:40~6:00 | 기술: 근거 대조, 단계적 조치, STT 비교 |
| 6:00~7:00 | 평가와 한계, 3단계 확장 계획 |

### 시연 대비

- 짧은 시험 음성(`submission/test-audio/test-call.mp3`)을 씁니다. CPU STT는 음성 1분에 약 70초가 걸립니다.
- 발표 직전 `/healthz`와 `/healthz/stt`를 확인합니다.
- 네트워크나 STT가 실패하면 미리 준비한 예시 통화 또는 녹화 영상으로 바로 넘어갑니다.
- 시연 가족 계정에 남은 기록과 잠금 상태를 미리 초기화합니다.
- 접근성 권한과 폴더 연결 상태를 미리 확인합니다.

## 5. 예상 질문

| 질문 | 답변 요지 |
|---|---|
| Claude를 호출한 것뿐 아닌가요? | 판정은 외부 API입니다. 판정 기준과 스키마, 근거 대조, 조치 정책, STT 서빙, RAG, 앱을 직접 구현했습니다. 자체 학습 모델은 없습니다. |
| 탐지율 100%를 믿을 수 있나요? | 합성 60건이므로 믿으면 안 됩니다. 95% 신뢰구간은 탐지율 88% 이상, 오탐률 12% 이하이며 실제 통화는 미측정입니다. |
| RAG는 효과가 있나요? | 현재 평가에서는 탐지·오탐 차이가 없습니다. 평가셋이 작아 효과를 말할 수 없고 실제 통화로 다시 측정합니다. |
| 잠금이 오탐이면요? | 0.9 이상과 녹취 근거가 있어야 동작하고, 가족 해제, 10분 대기, 1시간 만료로 복구됩니다. |
| 잠금을 우회할 수 있나요? | 접근성 권한을 끄거나 앱을 지우면 막을 수 없습니다. 금융사 연계의 이체 지연이 장기 방향입니다. |
| 통화 상대방 동의는요? | 통화 상대의 음성도 전송되므로 실제 서비스 전에 법률 검토와 동의 절차가 필요합니다. 현재는 시험 음성만 사용합니다. |
| 음성은 외부로 나가나요? | 평상시 음성은 자체 STT에서 처리합니다. 부하, 장애, 5분 초과 때는 OpenAI로 가고, 글자 기록은 Anthropic으로 갑니다. |
| S3 음성은 어떻게 보호하나요? | 기기에 AWS 키를 두지 않고 서버가 발급한 임시 링크로 올립니다. 퍼블릭 차단, 최소 권한, KMS, 보관 기간 제한, 접근 기록은 실제로 적용된 항목만 말합니다. |
