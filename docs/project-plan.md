# CodySafe 기획안 — 「찍기 전에」 QR 판독 (가족 보안 플랫폼의 첫 모듈)

> 코디세이 AI 해커톤 2026 · 팀 유레카 · 주제 02 「AI 기반 정보보호 서비스」
>
> 상태: 2026-10-31 12시 기준 제안. 팀 합의 전이며, 확인 뒤 고치고 바뀐 것은 맨 끝 '결정 기록'에 적습니다.
> 절 순서는 발표자료 필수 7항목(ⓐ–ⓖ)과 같습니다. 이 문서는 발표자료의 근거 문서이고, 발표자료는 이 내용을 표지 빼고 10쪽 안으로 줄여 다시 짭니다.

## 0. 한 장 요약

- **한 장면:** 밤, 공유 킥보드 손잡이의 QR. 일반 카메라로 비추면 링크가 뜨고 누르면 열립니다. 「찍기 전에」는 덧댄 스티커와 "인쇄물: 공유킥보드 ≠ 실제 주소: 처음 보는 도메인"을 보여 주고 '위험'으로 멈춥니다.
- **무엇을 더하나:** 지금의 확인 도구는 QR 속 주소를 검사합니다. 우리는 **인쇄물(덧댄 스티커, 인쇄된 기관 이름)과 알려진 목록에 없는 새 주소**를 함께 봅니다.
- **직접 개발:** URL 분류 모델(시간 분할 평가), 스티커 탐지 모델(합성 데이터 생성기 포함), 인쇄물 ↔ 도메인 대조 규칙, 점수 결합.
- **플랫폼:** CodySafe는 사기 대응에 도움이 필요한 가족(부모님·아이)을 가족이 함께 지키는 플랫폼이고, 「찍기 전에」는 그 첫 모듈입니다. 보호자에게는 판정 결과만 갑니다.

## 1. 문제 정의·목표 사용자 (ⓐ)

### 1-1. 문제
- 공유 킥보드·주차 고지서·공공 안내문의 정상 QR 위에 가짜 QR 스티커를 덧붙여 악성 앱 설치나 개인정보 입력을 유도하는 '큐싱'이 정부 합동 주의 대상입니다. 국내 확인 유형에 "공유형 킥보드에 부착된 정상 QR코드 위에 큐싱 스티커를 덧붙이"는 방식이 있습니다([개인정보보호위원회 관계부처 합동 보도자료, 2024-10-23](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=10698)).
- 스미싱 탐지는 2022년 37,122건에서 2024년 2,196,469건으로 늘었습니다. 3년 누적 2,736,891건 중 공공기관 사칭이 59.4%, 청첩장·부고장 같은 지인 사칭이 15.5%입니다([금융위원회 보도자료](https://www.fsc.go.kr/no010101/83889)). 스미싱 전체 통계이며 큐싱만의 피해 규모는 아닙니다.
- 지금의 확인 방법(공식 안내에서 확인한 범위, 2026-10-31):
  - KISA 보호나라: QR 사진을 분석해 10분 안에 회신(같은 금융위원회 자료).
  - KT '안심 QR': 스미싱 DB 등으로 판정([KT](https://inside.kt.com/html/safety/secure_QR.html)).
  - 카스퍼스키 QR Scanner: QR 해독, URL 검사, 미리보기, 악성·피싱 알림([카스퍼스키](https://support.kaspersky.com/QRSAndroid/1.3/en-us/94042.htm)).
  - 안랩 V3 Mobile Security 'QR코드 검사': 콘텐츠가 URL이면 악성 여부 검사([안랩](https://www.ahnlab.com/ko/product/v3-mobile)).
- **빈칸:** 위 안내에서는 인쇄물 위에 덧댄 스티커나 인쇄된 기관 이름을 보는 기능 설명을 찾지 못했습니다. KT 안내와 카스퍼스키 블로그는 오히려 "스티커가 덧붙여지지 않았는지 사람이 확인하라"고 합니다([KT 같은 페이지](https://inside.kt.com/html/safety/secure_QR.html), [카스퍼스키 블로그](https://www.kaspersky.com/blog/qr-code-threats/39789/)). 각 서비스가 알려진 목록에 없는 새 주소를 얼마나 잡는지는 확인하지 못했습니다.

### 1-2. 목표 사용자
1. 킥보드·주차 고지서·공공 안내문 QR을 자주 찍는 20–50대 스마트폰 이용자
2. 부모님 폰을 챙기는 자녀(가족 보호 네트워크로 판정 결과를 받는 사람)

## 2. 해결 방안·주요 기능 (ⓑ)

### 2-1. MVP 기능 (11-01 13:00 제출 목표. 구현 확정 목록이 아니며, 실제 상태는 README '구현 상태' 표)
1. **덧댄 스티커 탐지:** 카메라 화면에서 QR 둘레의 이중 테두리, 광택 차이, 가장자리 들뜸을 찾아 빨간 테두리로 표시합니다.
2. **인쇄물 ↔ 주소 불일치:** 인쇄물 글자(OCR)에서 기관·브랜드 이름(예: ○○구청 과태료, 공유 킥보드 회사)을 읽고, QR 속 주소의 도메인과 맞는지 봅니다.
3. **새 주소 판정 모델:** 알려진 목록에 없는 주소도 피싱 URL로 학습한 URL 분류 모델로 위험 점수를 냅니다.
4. **결과 화면:** 정상 / 주의 / 위험 / 판정 불가 + 근거 3줄 + '공식 앱으로 열기'. 정상 QR이 초록으로 통과하는 장면은 기능 시연이고, 오탐이 적다는 근거는 정상 URL 정답셋의 숫자로 따로 보입니다.
5. **(선택) 가족에게 결과 보내기:** 2-3절 조건을 지킬 수 있을 때만. 11-01 06:00까지 안 되면 빼고 확장 계획(11절)에만 둡니다.

### 2-2. 화면 흐름 (CodySafe 화면에 붙이기)
- 기능 10 '스미싱·피싱 URL 탐지'의 'QR 코드' 탭 → 스캔 → 결과 화면 → (위험이고 본인이 공유를 고르면) 기능 9 '가족 보호 네트워크'의 '최근 알림'에 "어머니 폰: 위험 신호 1건 감지 · 10:42 · 기관 사칭 의심"처럼 한 줄.
- 기능 10의 '문자·링크' 탭에도 같은 URL 분류 모델을 붙입니다.

### 2-3. 판정·개인정보 원칙
- **단정하지 않습니다.** 스티커가 보이거나 주소가 낯선 것 하나로 '피싱'이라 하지 않고 세 신호를 합쳐 '주의'와 '위험'을 나눕니다. '정상'은 '안전 보증'이 아니라 '드러난 위험 신호 없음'입니다. 스캔 실패·OCR 불확실·서버 오류는 '정상'이 아니라 '판정 불가'입니다.
- **데이터가 어디로 가나:** 판정을 서버에서 하면 사진이나 주소가 판정 서버로 전송될 수 있습니다. 기기 안 처리 범위, 서버로 가는 항목, 보관 여부는 구현한 뒤 확인해 README에 적고, 확인 전에는 '원문이 기기 밖으로 나가지 않는다'고 말하지 않습니다.
- **가족 공유:** 본인이 공유를 고르고, 확인된 보호자와 연결된 경우에만 보냅니다. 보내는 것은 판정 등급, 일반화한 위험 근거, 시각으로 제한하고, 사진과 주소 원문은 넣지 않습니다. 연결 해제와 보관 기간을 안내합니다. 본인 확인·보호자 연결을 구현하지 못하면 모의 계정 시연이나, 사용자가 직접 공유하는 판정 카드 내보내기로 한정합니다. 감시가 아니라 보호라는 점을 발표 첫 장에 씁니다.

공식 안내에서 확인한 범위입니다(2026-10-31). '안내 없음'은 안내에서 설명을 찾지 못했다는 뜻이고, 기능이 없다는 단정이 아닙니다.

## 3. 활용 AI 기술·직접 개발 범위 (ⓒ)

| 층 | 무엇 | 직접 개발 | 비교 기준 |
|---|---|---|---|
| URL 분류 모델 | 문자 단위 CNN 또는 소형 한국어 BERT 미세조정. 피싱 URL + **따로 만든 정상 URL 정답셋**(공공기관·킥보드·주차 앱 공식 도메인 포함) | 학습, 시간 분할 평가 | 학습 시점 목록과의 문자열 정확 일치, 길이·특수문자 규칙, 외부 LLM에 바로 묻기 |
| 스티커 탐지 모델 | 소형 객체 탐지 모델. 목표: 합성 5천 장 학습 + 실사 50장 시험 | 합성 데이터 생성기, 학습, 실사 시험 | 공식 안내에서 찾지 못한 기능이라 기준선은 '탐지 없음' |
| 인쇄물 대조 | 한국어 OCR → 기관·브랜드 사전 ↔ 도메인 대조 규칙 | 사전, 대조 로직 | QR 주소만 보는 방식 |
| 점수 결합 | 세 신호 → 정상·주의·위험·판정 불가 + 근거 3줄 | 결합 규칙, 근거 문장 | URL 신호 하나만 쓰는 방식 |
| 링크 미리보기(시연 한정) | 팀이 만든 **로컬 모의 페이지**에서만 마지막 입력창(주민번호·인증번호 칸)이 있는지 확인 | 직접 | 없음 |

- 사용자가 넣은 주소나 실제 피싱 주소를 서버가 대신 열어 보는 기능은 이번 MVP에 넣지 않습니다(내부망 접근·리디렉션·악성 파일 위험). 외부 URL 미리보기는 따로 안전성을 검토한 뒤 확장합니다.
- '직접 개발'은 남이 만든 모델을 그대로 부르는 것이 아니라, 우리가 만든 데이터·학습·평가·결합 층이 있다는 뜻입니다. 외부 모델과 도구는 7절 표에 모두 적습니다.

## 4. 데이터·평가 설계

### 4-1. 데이터
- 피싱 사이트 URL: [한국인터넷진흥원 피싱사이트 URL, 공공데이터포털](https://www.data.go.kr/data/15143094/fileData.do) 131,752행(탐지 날짜·URL 열, 로그인 없이 받음, 이용허락범위 제한 없음, 2026-10-31 포털 표기 확인), 이전 판 27,582행([공공데이터포털](https://www.data.go.kr/data/15109780/fileData.do)). 유효 행 수·날짜 분포·중복은 받은 뒤 확인합니다.
- (미사용 후보) [AI Hub 스미싱 합성 데이터](https://www.aihub.or.kr/aihubdata/data/view.do?dataSetSn=71983)(내국인 신청 필요).
- 정상 URL 정답셋: 공공기관·공유 킥보드·주차 앱 공식 도메인 등 팀이 목록을 만들고, 만든 기준을 함께 둡니다.
- 스티커 사진: 팀이 합성(재질·조명·각도 5종) + 실사 50장(목표). 실사는 만든 사람과 시험한 사람을 나누고, 실제로 모은 수를 따로 적습니다.

### 4-2. 평가
- **시험 전에 고정할 것:** 정상·덧댄 스티커 사진 수와 촬영 조건, 사진을 나누는 단위(같은 소품 사진이 학습과 시험에 섞이지 않게), URL 학습·검증·시험의 날짜 경계와 표본 수. 등록 도메인 기준으로 겹치지 않게 나누고, 판정 기준값은 검증셋에서만 정합니다. 고정한 시험셋으로는 조정·재학습하지 않습니다.

| 대상 | 지표 | 방법 |
|---|---|---|
| URL 분류 모델 | 새 주소 재현율, 정상 URL 오탐률, PR-AUC | 시간 분할 + 도메인 분리. 같은 시험셋에서 규칙 기준선과 비교 |
| 스티커 탐지 모델 | 실사 시험 정탐·오탐 수 | 합성으로 학습, 실사로만 시험. '스티커 있음'과 '사기임'의 정답을 따로 매김 |
| 전체 판정 | 정상·주의·위험·판정 불가 혼동표 | 같은 시험 사례에서 URL만 / URL+인쇄물 대조 / 세 신호 전체 비교 |
| 처리 시간 | 스캔 → 판정 초 | 휴대폰에서 실측. 재기 전에는 숫자를 말하지 않음 |

- 문자열 정확 일치 기준선은 학습 시점까지 확보한 목록에 없는 주소를 정의상 못 잡습니다. 이것은 이 단순 기준선의 성질이지 상용 보안 서비스의 탐지율이 아닙니다.

### 4-3. 결과 보기 전에 정한 줄
- URL 분류 모델이 시간 분할 시험에서 단순 규칙보다 낫지 않으면, 그 결과를 그대로 공개하고 스티커·인쇄물 대조를 주인공으로 둡니다.
- **예비안으로 바꾸는 조건:** 10-31 21:00 점검에서 스티커 탐지 모델이 실사 사진을 못 잡고, **동시에** URL 분류 모델도 단순 규칙을 못 넘으면 예비안 '녹음 속 개인정보 지우개+'(STT가 잘못 받아써도 개인정보를 잡는지 재는 한국어 평가셋)로 바꿉니다.

## 10. 위험과 대책

1. **스티커 탐지 모델이 '우리가 붙인 스티커'만 맞힐 위험** → 합성 조건을 다양하게, 실사 시험은 다른 팀원이 만든 사진으로, 같은 소품 사진이 학습·시험에 섞이지 않게, 영상에 '합성 학습·실사 시험' 표기.
2. **"KT 안심 QR·카스퍼스키·안랩과 뭐가 다르냐"** → 2-4절 표로 답합니다: 공식 안내에서 확인한 것은 QR 속 주소 검사이고, 우리는 인쇄물(스티커·글자)을 더합니다. 그쪽에 없다고 단정하지 않습니다.
3. **과장 위험** → 처리 시간, 기기 안 처리, '차단'은 실측·구현한 만큼만 말합니다. 판정은 근거와 함께 '주의/위험'으로.
4. **실제 피싱 주소·악성 파일 취급** → 학습엔 URL 문자열만, 접속하지 않음, 미리보기는 로컬 모의 페이지만.
5. **URL 분류 모델이 규칙보다 못한 경우** → 결과를 그대로 공개하고 스티커·인쇄물 대조를 주인공으로(4-3절).
6. **개인정보** → 판정 서버로 가는 항목·보관 여부를 구현 뒤 확인해 적고, 가족 공유는 본인 선택·보호자 확인·판정 결과만(2-3절).
7. **GPU 서버 한 대를 팀이 같이 씀** → 예약 한 줄 규칙, 가중치·결과는 서버 밖에도 주기적으로 백업.
